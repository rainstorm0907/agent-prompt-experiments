# 조사 스킬은 필요할 때만 열리고, 조사를 맡겨도 조건이 남는가 (2026-10-25, 10-31)

## 딥다이브(deep-dive)가 뭔가

딥다이브는 내가 Rubato 공식 스킬로 넣은 조사 스킬이다. 스킬은 AI 에이전트가 일하다 필요할 때 스스로 열어 읽는 작업 안내 문서다.

이 스킬은 중요한 결정을 앞두고 근거가 서로 엇갈릴 때 쓰는 조사 방법을 적어 둔 것이다. 결정에 필요한 질문부터 세우고, 결정을 가르는 주장은 원문을 직접 열어 확인하고, 근거에 붙은 조건을 빼지 않고 모아서, 결론은 대신 내리지 않고 판단할 사람에게 넘기게 한다.

## 결론

스킬을 공식판에 넣기 전후로 세 가지를 쟀다.

1. **필요할 때만 열리나 (10-25).** 조사가 필요한 요청에서는 24번 중 23번 스킬을 열었다. 그런데 열면 안 되는 요청에서도 32번 중 4번 열었고, 넷 다 "이 코드 딥다이브해 줘" 같은 코드 읽기 요청이었다. 스킬 설명 한 줄을 "결정에 쓸 근거 조사"로 좁히자 그 요청에서는 6번 중 한 번도 열지 않았다.
2. **조사 결과를 제대로 정리하나.** 스킬이 없을 때는 12번 중 8번, 있을 때는 12번 모두 기준을 통과했다. 처음 짠 정리 시험은 설계가 잘못돼 결과를 쓰지 않고 새로 짰다(「한계」 참고).
3. **고친 본문도 괜찮은가 (10-31).** 스킬 본문을 고친 판과 기존 판을 비교했다. 미리 정한 확인 항목은 대부분 통과했다. 다만 고친 판에서는 "사용자의 우선순위나 취향에 달린 선택"을 사용자에게 돌려주는 부분이 두 번 다 빠졌다. 조사를 다른 에이전트에게 맡긴 경우에는 결과를 요약해 넘기는 사이 주장의 범위가 넓어진 곳도 두 군데 나왔다. 둘 다 고쳐서 반영했다.

반영: [PR #32](https://github.com/keepitmello/Rubato/pull/32) (스킬 추가, 설명 좁힘), [PR #39](https://github.com/keepitmello/Rubato/pull/39) (넘기기 전에 쓴 주장을 원문과 계산에 다시 대조, 사용자 몫 선택 돌려주기 되살림)

## 무슨 일이었나

중요한 결정을 앞두고 조사를 맡기면, 에이전트가 근거를 모으다 스스로 결론을 내리거나 결과를 요약해 넘기면서 원래 조건을 빠뜨리는 일이 있었다. 이를 줄이려고 딥다이브를 만들었다. 다만 스킬이 생기면 엉뚱한 요청에서도 열릴 수 있고, 열렸을 때 정말 나아지는지도 따로 확인해야 했다.

## 비교한 판

| 판 | 내용 |
|---|---|
| 스킬 없음 | 그때 공식판 스킬 묶음 그대로 |
| 첫 판 | 위 묶음에 딥다이브 첫 판을 더함 |
| 설명 좁힌 판 | 첫 판에서 스킬 설명 한 줄만 고침. 코드 읽기 요청과 헷갈리지 않게 "근거가 엇갈리는 결정에 쓸 조사"로 좁힘 |
| 기존 본문 / 고친 본문 (10-31) | 공식판 본문 / 정해진 단계를 차례로 밟던 방식을 "요청한 곳까지 한 조사 담당이 이어 가고, 넘기기 전에 쓴 주장을 원문과 대조"하는 방식으로 바꾼 본문 |

## 어떻게 쟀나

- 명령줄에서 한 번에 한 턴씩 돌렸다. 10-25에는 Claude Opus 5.5와 GPT-6.1 Sol, 10-31에는 Claude Opus 5.5를 썼다.
- 돌리기 전에 두 판이 모델에 실제로 보내는 요청을 미리 받아 비교했다. 스킬 목록의 딥다이브 항목 몇 줄 말고는 같았다.
- **스킬을 열었나:** 처음 여섯 번의 도구 사용 안에 딥다이브 문서를 읽었는지로 셌다. 조사가 필요한 요청 6가지와 열면 안 되는 요청 8가지를 판과 모델마다 2번씩(다시 잴 때는 3번) 돌렸다.
- **정리를 잘했나:** AI 채점자(Claude Opus 5.5) 한 명이 어느 판, 어느 모델의 답인지 모르게 채점했다. 스킬 이름도 가렸다. 기준은 문장 단위로 미리 나눠 두고 통과, 실패, 확인 불가로 매겼다.
- **고친 본문 비교 (10-31):** 같은 요청과 자료(가상의 가계부 앱이 은행 연동을 언제 물을지 정하는 자료)를 네 가지로 돌렸다. 기존 본문과 고친 본문을 각각 리드 에이전트가 직접 조사할 때와 한 에이전트에게 맡길 때로 나눴다. 칸마다 1번이고, 채점은 시험을 돌린 AI 세션이 원문을 읽고 했다(이름 가림 없음). 그 뒤 다른 회사의 모델(GPT)에게 같은 기록을 대조하게 해 놓친 곳을 찾았다.

## 결과

### 스킬을 열었나

| 요청 | Opus 스킬 없음 | Opus 첫 판 | Sol 스킬 없음 | Sol 첫 판 |
|---|---|---|---|---|
| 조사가 필요한 요청 | 0/12 | 11/12 | 0/12 | 12/12 |
| 열면 안 되는 요청 | 0/16 | 2/16 | 0/16 | 2/16 |

잘못 연 4번은 모두 "코드 딥다이브" 요청이었다. 설명을 좁힌 판으로 다시 쟀다(3번씩).

| 요청 | Opus 좁힌 판 | Sol 좁힌 판 | 첫 판 (Opus, Sol, 2번씩) |
|---|---|---|---|
| 코드 딥다이브 (열면 안 됨) | 0/3 | 0/3 | 2/2, 2/2 |
| 딥다이브를 직접 부탁 (한국어, 영어 등 세 가지) | 9/9 | 9/9 | 6/6, 6/6 |
| 채용 시장 조사 | 1/3 | 1/3 | 1/2, 2/2 |

"딥다이브"라는 말 없이 결정을 위한 조사를 맡기는 요청(채용 시장 조사)에서는 잘 열지 않았다. 이 점은 고치지 않고 기록만 했다.

### 정리를 잘했나 (다시 짠 시험, 이름 가린 채점)

| 요청 | Opus 스킬 없음 | Opus 좁힌 판 | Sol 스킬 없음 | Sol 좁힌 판 |
|---|---|---|---|---|
| 조사 결과를 다음 담당에게 넘길 정리 | 2/3 | 3/3 | 1/3 | 3/3 |
| 판단할 사람에게 줄 최종 정리 | 3/3 | 3/3 | 2/3 | 3/3 |

스킬이 없을 때 걸린 4번은 저마다 다른 데서 걸렸다. 넘기는 정리에 추천을 넣은 경우가 2번, 확인 안 된 사실을 단정한 경우가 1번, 사용자가 신경 쓰던 조건을 빠뜨린 경우가 1번이다. 스킬이 있을 때 12번 중 2번은 하위 에이전트를 부르는 순간 실행이 멈춰 답을 볼 수 없었다. 미리 정한 규칙대로 실패로 세지 않았다.

### 고친 본문 비교 (10-31)

| 항목 | 기존, 직접 | 고친 판, 직접 | 기존, 맡김 | 고친 판, 맡김 |
|---|---|---|---|---|
| 받은 자료를 그 자리에서 집계 | ✓ | ✓ | ✓ | ✓ |
| 외국 실험 결과의 핵심 조건을 빠뜨리지 않음 | ✓ | ✓ | 기록에만 | ✓ |
| 추천하지 않고 근거만 넘김 | ✓ | ✓ | ✓ | ✓ |
| 사용자 우선순위나 취향에 달린 선택을 돌려줌 | ✓ | 빠짐 | ✓ | 빠짐 |
| 여기서 조사를 멈추는 이유 | 없음 | ✓ | 없음 | 기록에만 |
| 다음 담당이 열 수 있는 기록 파일 | 없음 | ✓ | 작업 폴더 밖 | ✓ |

고친 판에 조사를 맡긴 경우, 범위가 넓어진 곳이 두 군데 있었다. 조사 기록에는 "목표 선택 구성 차이로는 설명되지 않는다"고 적혀 있었는데, 넘긴 결과와 최종 답에서는 "사용자 구성 차이로는"으로 넓어졌다. "10/20 이전 가입자 기준" 수치는 최종 답에서 기준 없이 전체 가입자 수치처럼 쓰였다.

## 결정

- 설명을 좁힌 판으로 스킬을 넣었다(PR #32).
- 고친 본문에서 빠진 "사용자 몫 선택 돌려주기"는 마무리 문장에 되살렸다. 넘기기 전에 쓴 주장을 원문과 계산에 다시 대조하는 단계도 더해 반영했다(PR #39). 빠진 원인이 본문에서 바로 보여서 비교를 다시 돌리지는 않았다.

## 한계와 측정 문제

- 표본이 작다. 스킬을 열었는지는 칸마다 2~3번, 정리는 3번, 고친 본문 비교는 1번이다. 고칠 후보를 거른 수준이다.
- **처음 짠 정리 시험은 쓰지 않았다.** "정리해 줘"만 받은 새 세션은 스킬을 거의 열지 않았다(넘기는 정리 6번 중 0번, 최종 정리 6번 중 3번). 자료 하나는 인용 출처 링크가 틀려 있었다. 시험에 숨긴 함정이 스킬 본문에 거의 그대로 적혀 있어서, 처음 보는 함정도 잡는지는 알 수 없었다. 그래서 자료를 새로 짰다.
- 다시 짠 시험은 요청에 "딥다이브"라는 말이 들어 있어 스킬이 매번 열렸다. 스킬을 연 뒤의 효과를 잰 것이고, 그냥 정리를 시켰을 때 스킬을 여는지는 재지 않았다.
- 몇몇 실행이 같은 임시 폴더에 같은 이름으로 파일을 내려받아, 다른 실행의 파일을 읽었을 수 있다. 실행이 이름을 댄 파일 94개는 끝난 뒤 지웠다.
- 다시 짠 시험 중 18번은 컴퓨터 부하로 실행 엔진이 시작되지 않아 빈 답으로 끝났다. 에이전트 행동이 아니라 시험 도구 실패라 빼고 다시 돌렸다. 이후 이런 실행은 자동으로 무효 처리하고 다시 돌리게 고쳤다.
- 첫 시험에서 앞 실행이 남긴 조사 기록을 뒤 실행이 읽은 일이 한 번 있었다. 그 실행은 다시 돌렸고, 이후에는 실행마다 작업 자리를 통째로 비웠다.
- 고친 본문 비교는 이름을 가리지 않은 채점이다. 다른 회사의 모델에게 같은 기록을 대조하게 해 보완했지만, 블라인드 결과로 읽으면 안 된다.
