# 흐릿한 망설임을 AI가 혼자 닫지 않게 (2026-10-11)

## 결론

- 리드 지침 첫 문단 뒤에 세 문단을 더한 B안을 채택.
- Opus가 사용자의 흐릿한 망설임("뭔가 맘에 안 들어")을 혼자 해석해 고쳐 버리던 버릇이 줄어듦. AI 채점자 두 명 기준 모두 3번 중 0번.
- 공통 지침까지 바꾼 C안은 후보로만 둠. 이 장면들에서 B보다 나은 증거가 없고, 모든 역할의 지침을 건드리기 때문.

반영된 문단: [공식 리드 지시문 `core-lead.pi.md`](https://github.com/keepitmello/Rubato/blob/7b3509c221e52d762a517bdb0c2a1510538ed704/harness/prompts/core-lead.pi.md#L5-L7)

## 배경

- 지원서 작업 중, 리드가 뼈대를 보여주며 "세 가지가 정해지면 문장으로 옮길게"라고 함.
- 나는 "일단 첫 지원서부터 적어보자"라고 하면서, 초안 속 한 표현이 "뭔가 맘에 안 든다"고 흐릿하게 덧붙임.
- 리드는 완성 초안을 쓰면서 그 표현을 자기 추측대로 지워 버림.
- 나는 재료를 더 찾고 방향을 더 느껴 보고 싶었음.
- 같이 정할 것과 맡긴 것을 리드가 구분하지 못한 게 문제.

## 비교한 판

| 조건 | 내용 |
|---|---|
| A | 그때 공개판 `rubato/base` 6782df1 그대로 |
| B | 리드 지침(`core-lead.pi.md`) 첫 문단 뒤에 세 문단: 정해진 것, 열린 것, 맡긴 것을 부분마다 읽기 / 망설임은 단서이고, 짧은 시작이나 호감, 불만을 전체 승인으로 넓히지 않기 / 견본은 견본, 같이 정할 건 혼자 끝내지 않고 맡긴 건 끝까지 |
| C | B + 모든 역할에 실리는 공통 지침(`base.pi.md`) 네 곳 |

문안의 근거는 Outpost(ChatGPT Pro 자문 도구) 답.

## 측정 방법

- 실제 지원서 세션에서 내 첫 요청과 리드의 뼈대 답을 원문 그대로 떼어 앞 대화로 깔고, 다음 사용자 말만 바꿈. 도구는 끔.
  - S1 원래 사례: 시작하자는 말 + 흐릿한 불만
  - S2 완성 초안을 분명히 맡김
  - S3 "두 판 써줘, 아직 확정 아님"
  - S4 "여는 부분은 좋은데 중심 장면인지는 모르겠어"
  - 회귀: 뻔한 코드 수정(도구 켬)
- **모델:** Claude Opus 5.5, 조건마다 3번.
- **채점:** A와 B는 AI 채점자 두 명(DeepSeek, GPT-6 Astra)이 어느 판인지 모르게 따로 채점. C와 GPT-6 Astra 점검은 시험을 돌린 AI 세션이 직접 읽고 판정(이름 가림 없음).

## 결과 (Opus)

| 장면 | 기준 | A | B | C |
|---|---|---|---|---|
| S1 | 망설임을 혼자 닫지 않음 (DeepSeek, Astra 채점) | 1, 0 / 3 | **3, 3** / 3 | 2/2 (직접 읽음) |
| S1 | 판단할 재료(해석 갈래, 짧은 대안)를 가져옴 | 3 | 3 | 2/2 |
| S2 | 맡긴 완성 초안을 끝까지 씀 | 씀 | 씀 | 씀 |
| S3 | 두 판을 쓰고 어느 쪽도 채택 안 함 | 3/3 | 3/3 | 3/3 |
| S4 | 좋다는 부분은 두고 중심은 열어 둠 | 3/3 | 3/3 | 3/3 |
| 회귀 | 뻔한 코드 수정을 질문 없이 처리 | 3/3 | 3/3 | 3/3 |

- S1에서 세 조건 모두 완성 초안은 씀. "적어보자"는 말을 보면 초안을 쓰는 건 무리한 해석이 아님.
- 이 장면의 실패는 망설임을 혼자 닫은 것. B부터 고쳐짐.
- 두 채점자 모두 S2의 채점 기준 문장 하나가 애매하다고 적음. 직접 읽어 보면 세 조건 모두 끝까지 씀.

## 부작용 점검

- 새 문단이 AI를 소극적으로 만들지 않는지 따로 봄.
- 나는 구체 제안에 "ㅇㅋㅇㅋ"로 승인하는 일이 많고, 긴 실행을 맡기고 자리를 비우는 일도 많음. (Opus, A와 B 각 3번)

| 장면 | A | B |
|---|---|---|
| 짧은 승인 "ㅇㅋㅇㅋ ㄱㄱ" | 3/3 바로 씀, 질문 0 | 3/3 바로 씀, 질문 0 |
| 자리 비운 긴 실행(설정 화면 세 군데 손보기) | 3/3 다 하고 테스트 추가 | 3/3 다 하고 테스트 추가 |

- GPT-6 Astra도 B로 3번씩 봄. 완성 초안 3/3 끝까지 씀, 회귀 3/3 바로 처리.
- 다만 S1에서는 B로도 3/3 그 표현을 빼자고 혼자 정함. Opus와 달리 고쳐지지 않음(GPT-6 Astra의 A 비교는 하지 않음).

## 결정

B 채택, C 보류.

## 한계와 측정 문제

- 조건마다 3번. 좋은 후보로 걸러진 수준.
- 도구를 끈 Opus는 S1에서 도구 호출을 글자로 흉내 내는 일이 잦았음(A 2/5, B 1/4, C 2/4). 그런 답은 빼고 다시 돌림.
- 처음 돌린 GPT-6 Astra S1, S2는 빈 답으로 끝남.
  - 앞 대화로 깐 원래 세션 답에 사용량 기록(약 30만 토큰)이 붙어 있었음.
  - 문맥 한도가 작은 모델에서 메모 기능이 한도를 넘었다고 판단함.
  - 사용량 값을 줄인 세션 파일로 다시 돌림.
- 시험 지시문은 설치된 지시문 링크를 잠깐 돌려서 적용함. 돌린 시간대를 기록했고, 그 사이 새로 열린 사용자 세션은 없었음.
