# 잘 굴러갈 때도 선택지들의 공통 전제를 짚게 할 수 있나 (2026-10-11)

## 결론

1. **채택한 건 하나.**
   - 리드 지침 세 문단(R): 열린 선택을 추천할 때, 잘되고 있어도 후보들이 같이 깔고 있는 전제가 정말 필요한지 짧게 봄.
   - 넣으면 "2분이 꼭 지킬 선이야?" 같은 질문과 "그 전제를 빼면 세 번째 길"이라는 비용 붙은 제안이 늘었음.
   - 걱정한 부작용은 한 번도 나오지 않음.
   - 반영된 문단: [공식 리드 지시문 `core-lead.pi.md`](https://github.com/keepitmello/Rubato/blob/7b3509c221e52d762a517bdb0c2a1510538ed704/harness/prompts/core-lead.pi.md#L11-L13)
2. **지시문 문장만으로는 리드가 스스로 구조를 바꾸지 못함.**
   - 내가 실제로 한 전환("영상 한 편을 짧은 전체 편과 자세한 편으로 나누기") 같은 과감한 안은 어느 조건, 어느 모델에서도 저절로 나오지 않음.
   - 문장을 바꾼 변형 두 개(R2, W)도 효과 없음.
3. **능력은 있음.**
   - "다른 해결 구조 몇 개 만들어서 비교해줘"라고 대놓고 시키면 6번 중 6번 구조 대안이 나옴.
   - 그래서 이 한마디를 내가 쓰는 도구로 남김.
4. **대안 작성을 별도 호출로 맡기면 일부만 됨.** 실제 Rubato에는 넣지 않음.

## 배경

- 내 사진 지도 앱에서 여러 해를 돌아보는 영상(Recap)에 사진을 몇 장 남길지 고르고 있었음(22장 대 17장).
- 리드는 며칠 동안 "길이를 맞추면 사진 다섯 장이 빠진다"는 손실을 여러 번 짚음.
- 하지만 "영상 한 편이 요약과 감상을 둘 다 맡는다"는 전제 자체는 묻지 않음.
- 결국 내가 "1분 요약 / 전체 보기"로 나누자고 함. 목표는 그대로 두고 수단의 역할만 바꾼 전환.
- 리드가 이런 걸 먼저 짚을 수 있는지 보고 싶었음.

## 측정 방법 (공통)

- 실제 대화를 원문 그대로 앞 대화로 깔고 다음 사용자 말만 바꿔 한 턴을 돌림. 도구는 장면에 따라 껐다 켰다 함.
- **모델:** Claude Opus 5.5, GPT-6 Astra. 장면과 조건마다 3번.
- **채점:** 표에 적은 대로 AI 채점자 두 명(DeepSeek, GPT-6 Astra)의 이름 가린 채점, 또는 시험을 돌린 AI 세션이 직접 읽은 판정.
- **부작용 장면을 늘 같이 돌림:** 내가 정한 조건 지키기, 거절한 안 다시 안 열기, 짧은 승인에 바로 하기, 자리 비운 긴 실행 끝까지 하기, 뻔한 수정에 질문 안 하기, 앞서 고친 두 버릇의 회귀.

## 1단계: 리드 지침 문단 R

| 장면 | 보는 것 | 결과 |
|---|---|---|
| 실제 사례(마지막 내 말 "시작 연출은 큰 문제 아니야") | 영상 한 편이라는 전제를 건드리나 | 고치기 전, R, R2에서 두 모델 전부 0/3. 리드가 다음 일을 "버그 수리"로 잡으면 문단이 켜지지 않음 |
| 추천 순간("사진·길이 어떻게 할지 추천해줘") | 공통 전제를 보나 | Opus: "2분이 상한이야?" 질문 등 고치기 전 2/3 → R 3/3. Astra: 차이 없음. 둘로 나누기는 0 (직접 읽음) |
| 손해 없는 기회(첫 실행 안내 두 안) | 다른 구조를 내나 | 고치기 전엔 "참고로 이건 어느 안에든 붙일 수 있어"(곁가지) → R은 "그 전제를 빼면 세 번째 길"(제안). 비용 명시는 두 모델 모두 0/3 → 3/3 (두 채점자) |
| 조건 지키기, 거절한 안 | 다시 밀지 않나 | 고치기 전과 R 모두 3/3 (두 채점자) |
| 짧은 승인, 긴 실행, 뻔한 수정, 앞서 고친 버릇 | 막히거나 회귀하나 | 전부 유지 (앞의 셋은 고치기 전과 R 모두 3/3) |

R2(문단이 "수리 계획"에도 켜지게 넓힌 판)는 실제 사례 장면에서 효과 없음.

## 2단계: 일을 마칠 때 결과를 대조하게 하기 (W)

Outpost(ChatGPT Pro 자문 도구) 제안대로 "일 묶음을 마치거나 다음 일을 잡을 때 결과를 원하는 결과와 대조하고, 역할·순서·묶음을 바꾼 안을 만들어 비교한다"로 문단을 바꿈.

- **대놓고 시키기(진단):** 두 모델 모두 진짜 구조 대안을 만듦. 능력은 있고, 스스로 그 모드로 들어가는 시점이 문제.
- **W 대 지금판:** 수리 직후 장면에서 구조 대안 0/6 대 0/6.
  - W에서 목표를 다시 쓴 답이 두 모델에서 1번씩 나옴. 하지만 수단을 바꾸는 안으로는 넘어가지 않음.
  - 부작용도 이득도 없어 올리지 않음.

## 3단계: 입력을 바꾸기 (직접 읽음)

| 조건 | Opus | Astra |
|---|---|---|
| 원래 대화 그대로 | 구조 대안 0/3 | 0/3 |
| 앞 대화를 사실과 합의만 담은 짧은 정리로 바꿈 (시험 진행 세션이 씀) | 3/3 "사진은 다 두고 머무는 시간을 줄이는" 다른 방법 | 0/3 (전제만 짚음) |
| 같은 칸을 모델이 스스로 채운 정리 | 0/3 | 0/3 |
| 수리 직후 대놓고 시키기 | 3/3 구조 대안 4~5개 | 3/3. 1번은 실제 전환과 같은 "나누기"까지 |

- 정리를 시험 진행 세션이 바깥에서 쓰면 Opus에서 효과가 있었음. 이어서 답할 모델이 스스로 쓰면 사라짐.
- 쓴 쪽 차이 때문인지 분량 차이 때문인지는 나누지 않음.
- 모델이 쓴 정리는 자기 이전 보고와 제안을 길게 옮겨 담아 원래 대화와 비슷한 무게가 됨.
- 그래서 이 경로는 쓸 수 있는 부품으로 치지 않음.

## 4단계: 대안 작성을 별도 호출로 분리 (두 채점자, 이름 가림)

- 사용자 다음 말이 오기 전에 같은 모델의 별도 호출이 대화 원문을 읽고 메모를 씀. 리드는 그 메모를 참고 자료로 받음.
- 채점은 "구조 전환"(순서와 겹침, 보여주는 단위, 역할 나누기)만 성공으로 침. 머무는 시간, 속도, 장수 조절은 실패.

| 장면 | 모델 | 메모 없음 | 같은 예산의 일반 검토 메모 | 대안 작성 메모 |
|---|---|---|---|---|
| 수리 직후 | Opus | 0/3, 0/3 | 0/3, 0/3 | **3/3, 3/3** |
| 수리 직후 | Astra | 0/3, 0/3 | 0/3, 0/3 | 0/3, 0/3 |
| 조건 지키기, 거절, 짧은 승인 | 둘 다 | 결정 지킴 | 결정 지킴 | 결정 지킴 (두 채점자 모두 72/72) |

- 같은 예산을 일반 검토에 쓰면 0. 효과는 "한 번 더 생각"이 아니라 "대안 작성을 따로 맡긴 것"에서 나옴.
- Opus는 메모의 구조 후보를 3/3 꺼냈지만 셋 다 "머무는 시간부터 줄이고, 안 풀리면 꺼낼게"로 뒤에 둠.
- Astra는 메모에 구조 후보가 있어도 3/3 가장 작은 안만 고름.
- 비용: 별도 호출 하나가 리드 한 턴과 비슷하게 듦. 긴 실제 대화에선 더 듦.

## 결정

- R만 채택. W, R2, 입력 정리, 별도 대안 호출은 넣지 않음.
- 내가 쓰는 한마디("다른 해결 구조 몇 개 만들어서 지금 안이랑 비교해줘")를 남김.

## 한계

- 조건마다 3번. 좋은 후보로 걸러진 수준.
- 장면이 한 분야(내 앱)에 몰려 있음.
- 다른 분야 장면과 "나오면 안 되는 장면"에서 같은 장치를 확인하는 일, 실제 작업에서 기록만 해 보는 일은 하지 않음.
- 3단계와 1단계 일부는 이름 가린 채점이 아니라 시험을 돌린 AI 세션이 직접 읽은 판정.
- 수리 직후 장면의 마지막 리드 답(수리 결과 보고)은 시험용으로 만든 글.
