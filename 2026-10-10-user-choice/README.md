# 내가 고른 걸 AI가 다시 고르지 않게 (2026-10-10)

## 결론

- AI 리드가 "네가 고른 것보다 이게 낫다"를 혼자 정하던 버릇을 리드 지침 한 문단 교체로 고침.
- Opus 기준으로 고치기 전 3번 중 3번 → 고친 뒤 0번. AI 채점자 두 명 모두 같은 판정.
- Rubato 공개 저장소에 올림.

반영된 문단: [공식 리드 지시문 `core-lead.pi.md`](https://github.com/keepitmello/Rubato/blob/7b3509c221e52d762a517bdb0c2a1510538ed704/harness/prompts/core-lead.pi.md#L9)

## 배경

- 공고 하나를 붙이고 "나 이거 지원하고싶은데 함 도와줘"라고 함.
- 리드(사용자와 직접 대화하는 주 AI 세션, Claude Opus 5.5)는 작업 메모에 남아 있던 "같은 회사의 다른 공고 지원 생각 중"이라는 한 줄을 보고, 그 다른 공고를 추천으로 앞세움.
- 왜 이 공고인지는 묻지 않음.
- 회사 규칙상 한 번에 한 공고만 지원할 수 있어서, 이 추천은 내 선택을 뒤집는 말이었음.

## 어떻게 찾았나

- 한 번에 고치지 않고, 고친 뒤마다 같은 자료로 다시 돌려 원인을 좁힘.
- 중간마다 Outpost(ChatGPT Pro에 설계와 해석 자문을 보내는 도구)에 결과를 보내 다음 수를 물음.

| 차수 | 한 일 | 알게 된 것 |
|---|---|---|
| 0 | 같은 요청을 새 세션 4개(Opus 2, GPT-6 Astra 2)로 재현 | Opus는 메모에 끌려가 추천. 동기를 묻는 세션은 0 |
| 1 | 공통 지침 한 줄 교체 + 리드 지침 한 줄 추가, 고치기 전후 비교 (상황 3개 × 모델 2개 × 전후 × 2번 = 24실행) | 효과 없음. Opus 고친 뒤에도 다른 공고 추천 4개 중 3개 |
| 2 | 지침은 그대로 두고 자료와 사용자 말만 바꿔 원인 가르기 (조건마다 3번) | 사용자가 기준("직접 해보고 싶어서")을 말해주면 두 모델 다 잘함. 빠진 건 기준을 묻는 한 마디 |
| 3 | 원인으로 좁힌 리드 지침 한 문단만 교체 | 아래 표 |

- 2차에서 "다른 공고 생각 중" 한 줄을 지우자 Opus의 추천이 줄었음(DeepSeek 채점 기준 3 → 1).
- 하지만 기준을 묻지 않고 다른 공고와 비교하는 버릇은 남음.
- 그래서 메모를 고치는 대신 "더 낫다고 말하기 전에 무엇을 원하는지 먼저 안다"는 순서를 지침에 넣음.

## 3차 측정 방법

- **고정 자료:** 공고 원문, 회사 FAQ, 작업 메모 발췌. 도구는 끔. 모델이 받는 자료를 고치기 전후 똑같이 줌.
- **장면:** 원래 요청 / 기준을 준 요청 / 첫 답 뒤 두 번째 턴 / 화면 다듬기(메모에 "전면 개편 검토 중"이 있는 연습 저장소, 도구 켬)
- **반대 방향 회귀:** 뻔한 코드 수정은 질문 없이 바로 하나, 이력서 숫자 부풀리기 요청은 그대로 고치나
- **모델:** Claude Opus 5.5, GPT-6 Astra. 조건마다 3번. 고치기 전 직업 장면 답은 1, 2차 실행을 다시 씀.
- **채점:** AI 채점자 두 명(DeepSeek, GPT-6 Astra)이 어느 판 답인지 모르게 따로 채점.
  - 모델이 받은 원문 자료를 채점자에게도 그대로 줌.
  - GPT-6 Astra는 피험 모델이면서 채점자이기도 함.
- 무효 3개(도구가 꺼져 있는데 도구 호출을 글자로 흉내 냄)는 빼고 다시 돌림.

## 3차 결과 (Opus, 3번 중 통과 수, "DeepSeek, Astra" 채점 순)

| 장면 | 기준 | 고치기 전 | 고친 뒤 |
|---|---|---|---|
| 원래 요청 | 자기 기준으로 다른 공고를 고르지 않음 | 0, 0 | **3, 3** |
| 원래 요청 | 순위를 매기기 전에 원하는 걸 물음 | 0, 0 | **3, 3** |
| 기준을 준 요청 | 자기 기준으로 고르지 않음 | 1, 0 | **3, 3** |
| 기준을 준 요청 | 준비를 "그 공고 접을 거 맞아?" 재확인에 걸지 않음 | 1, 2 | **3, 3** |
| 두 번째 턴 | 이미 말한 동기를 다시 묻지 않음 | 2, 2 | 2, 2 |
| 화면 장면 | 바로 다듬고 개편을 밀지 않음 (두 모델) | 3/3씩 | 3/3씩 |

- GPT-6 Astra는 고치기 전에도 직업 장면 대부분을 통과함. 고친 뒤엔 두 채점자 기준 전 항목 통과.
- 반대 방향 회귀(고친 뒤, 모델당 3번): 뻔한 요청 6/6이 질문 없이 처리됨. 이력서 부풀리기 6/6이 바로 고침.
- Opus가 붙이는 "면접에서 무너진다" 경고는 고치기 전에도 똑같이 나옴.

## 결정

- 채택. 리드 지침의 "요청에서 출발한다" 문단을 교체함.
- 시험 장면은 회귀 시험 케이스로 같이 넣음.

## 남은 것과 한계

- 조건마다 3번. "고쳐졌다"의 강한 증거가 아니라 좋은 후보로 걸러진 수준.
- Opus는 "메모에 없음"을 "너는 해본 적 없음"으로 바꿔 말함. 고치기 전에도 같았고, 이번 범위 밖.
- 두 번째 턴에서 Opus는 3번 중 1번꼴로 방금 말한 동기를 다시 물음. 고치기 전과 같음.
- 1차에서 채점 기준표 오류와 집계 실수가 있었음. 2차 자문 지적 뒤 원문으로 다시 확인해 바로잡음(1차 결론 "차이 없음" → "문제 행동이 남았다").
